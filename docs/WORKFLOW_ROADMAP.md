# Workflow roadmap: from inputs to interpretation

Start here to understand the repository before running anything. This is the conceptual map; [TUTORIAL.md](TUTORIAL.md) supplies executable commands, and [RESULTS_GUIDE.md](RESULTS_GUIDE.md) defines every result column and gives worked interpretations.

## The question this workflow addresses

Which expression differences among cells can be described by partitions of a supplied clone/cellular tree, and how consistently do the fitted patterns recur when cells are subsampled?

The workflow starts with an existing tree, clone labels and normalized gene expression. It does not infer a trustworthy genealogy from expression. A tree branch defines a partition: cells descended from that branch versus other cells. A branch predictor is 1 for descendant cells and 0 otherwise. Different branches can overlap, be nested or encode equivalent fitted patterns, so selected coefficients do not uniquely identify historical changes.

The overall process is: check inputs → prepare tree partitions → prepare genes/expression → fit and compare methods → assess stability and working model complexity → repeat over genes → produce an interpreted report.

## Inputs and the unit of analysis

Three essential inputs establish the analysis:

1. A Seurat RDS with an explicitly chosen normalized assay/layer. Layer names alone do not establish the normalization scale.
2. A headered tab-separated table with `cell_id` and `clone_id`. These map each cell to its clone.
3. One explicitly rooted Newick tree whose tips correspond to the mapped cells.

Candidate genes can come from an existing clone DEG table or a user list. A DEG table has `gene`, `clone_id`, `p_val`, `p_val_adj`, `avg_log2FC`, `pct.1` and `pct.2`; these are upstream evidence, not new tests performed by the branch models. Explicit lists avoid requiring a DEG table.

The fitted response remains **one expression value per cell per gene** in both tree modes. Sample/site labels are optional descriptive information, not required grouping variables. The current implementation does not automatically adjust for sample/site confounding.

## Two tree representations, using the same cells

| Representation | What changes | What it can describe | How to use it |
|---|---|---|---|
| Collapsed | Retains whole-clone partitions; cells in the same clone share predictor values. | Expression patterns between clones or clone clades. | Primary analysis. Requires compatible monophyletic clones under the supplied tree. |
| Uncollapsed | Retains eligible cellular partitions after the branch filters. | Candidate subdivisions inside clones as well as between clones. | Exploratory analysis. Expression consistency does not validate within-clone ancestry. |

“Collapsed” refers to the predictor topology, not averaging the expression response into four clone observations. Many cells can share the same predictor pattern. Those cells are not automatically independent biological replicates.

Pseudobulking is deferred. In the initial dataset, site replication was too limited for some clones, and aggregation would remove individual cells' branch membership. It would not solve the scientific question simply by producing fewer rows. A future pseudobulk extension would need an appropriate replicated design and a clear estimand.

## The numbered scripts: what each step contributes

| Step / script | Main action | Main evidence to inspect | Decision before continuing |
|---|---|---|---|
| 0 — `00_install_packages.R` | Check required R packages; install missing ones when requested. | Availability/load checks and session information. | Is the same R library visible to later scripts? |
| 1 — `01_inspect_inputs.R` | Inspect layers, metadata and cell overlap. | One input report with cell/clone counts and mismatches. | Are IDs aligned and normalized data available? |
| 2 — `02_prepare_tree.R` | Audit clone monophyly; construct branch dictionaries and sparse designs. | Clone checks, branch inclusion/exclusion, rank, saved tree/designs and collapsed figure. | Is collapse appropriate, and are filters/root limitations understood? |
| 3 — `03_prepare_expression.R` | Reuse original DEG filtering/ranking when supplied; extract requested normalized expression in saved tree order. | Gene QC, candidate ranking, clone summaries and prepared expression. | Are genes finite/variable and the scale/order correct? |
| 4 — `04_fit_collapsed_cells.R` | Fit one gene with EN, weighted linear models and explicit contrasts. | Coefficients, contrasts, training metrics, predictions, comparison figure and collapsed selected-tree figure. | What clone-level expression pattern is observed? |
| 5 — `05_validate_models.R` | Validate the supplied pilot with cell subsampling and separate working-likelihood refits. | Per-term stability, iteration statuses, IC/equivalent spaces and saved samples. | Is the pattern stable under this sampling scheme, and what was estimable? |
| 6 — `06_fit_uncollapsed_cells.R` | Fit eligible cellular predictors; add within-clone/sister contrasts and a selected-tree view. | Same fit evidence plus cellular contrast support and tree figure. | Does extra detail describe a candidate subdivision, with its uncertainty acknowledged? |
| 7 — `07_run_gene_panel.R` | Reuse04/06 and shared05 for each chosen gene; checkpoint and summarize. | Panel list, per-stage status/logs, per-gene results and common summary. | Are results consistent across different expression patterns, with failures explicit? |
| 8 — `08_report_results.R` | Read saved outputs and generate integrated interpretation, combined tables and source records. | Markdown report, linked evidence, overview figure and column definitions. | Do conclusions follow the estimates, denominators and assumptions? |

Script 05 is used twice in a full pilot: **04 → 05 validating 04 → 06 → 05 validating 06**. The second validation uses a different pilot and output prefix; it does not require repeating the collapsed validation. Module 7 performs this sequence per gene automatically. Module 8 reads those existing results; it does not refit them.

These scripts package that analysis into small inspectable steps, with explicit provenance and interpretation limits.

## What the three methods estimate

| Method | Estimate | Useful interpretation | Common mistake |
|---|---|---|---|
| Elastic Net | Simultaneous penalized branch contributions; some coefficients shrink to zero. | A compact description of expression using the eligible branch predictors. | Calling every nonzero branch an independently identified ancestral shift. |
| Weighted linear model | Unpenalized coefficients in an independent basis spanning the saved design. | A flexible training reference and expression reconstruction. | Treating basis choice as biological branch selection or better training fit as validated prediction. |
| Explicit contrasts | Defined inside-minus-outside group-mean differences. | Direct descriptive differences for specified clades or within-clone groups. | Comparing them numerically to EN/basis coefficients as if the reference groups were identical. |

Clone-balanced fitting weights give each clone equal total contribution, using inverse cell count rescaled to mean one. These are balancing weights, not known measurement-precision weights. Collapsed contrasts give equal weight per clone on each side. Uncollapsed contrasts compare actual cells within the same clone, either against the remaining cells or a sister group under the immediate parent.

Coefficients/contrasts use the prepared response scale. They are not automatically the upstream DEG `avg_log2FC`. Read the group/reference definition before interpreting the magnitude or sign.

## Four different kinds of evidence

1. **Observed expression and training fit:** clone means, detection and fitted residuals describe the available cells. A flexible unpenalized model can fit training data better simply by using more directions.
2. **Tuning CV:** clone-stratified cell folds choose EN regularization. They describe interpolation within represented clones, not independent-patient/sample or held-out-clone prediction.
3. **Resampling stability:** by default,100 subsamples retain 80% of each clone without replacement, recompute balancing weights and retune EN on the fixed tree. Selection/sign frequencies and effect ranges describe this procedure. Read every term's denominator; a completed method can still have unavailable individual contrasts.
4. **Working AIC/BIC:** separate ordinary unweighted Independent and Identically Distributed (IID) Gaussian ML refits compare evaluated prediction spaces for the same gene/cells/scale. They penalize complexity differently, use a different objective from balancing, and do not correct dependent cells, confounding or post-selection. The uncollapsed search is bounded. Equivalent spaces can have different branch names. Never rank different genes using their raw AIC/BIC.

None of these validates the biological root, fixes uncertain topology or supplies independent biological replication. NA/non-estimable means an estimate was unavailable; it is not a measured zero. Subsampling quantiles are not confidence intervals, and selection frequencies are not p-values.

## Gene selection and scaling

Module 3 decides which genes are prepared. Module 7 decides which prepared genes are fitted.

- For a small chosen set, use `--genes GENE1,GENE2`.
- For many genes, use `--gene_list inputs/panel.txt`, a headerless one-gene-per-line file. All genes must already be prepared.
- With neither argument, Module7 chooses up to five descriptive examples: pilot anchor, largest remaining clone difference, sparse detection, broad detection, then smallest remaining clone difference.

A prepared 100-gene matrix does not mean Module 7 automatically runs 100 genes. The list controls explicit runs. The default panel is relative to the prepared candidates, so its weakest clone difference is not necessarily a null control. The five-gene example is sufficient for this development; larger biological analyses are separate work.

## Where to find results

Ordinary current-data defaults place pilot results at `results/module02.*`, `module03.*`, `module04.*`, `module04_validation.*`, `module06.*` and `module06_validation.*`. Module 7 groups outputs by gene:

```text
results/module07/
├── module07.panel.tsv          # what was chosen and why
├── module07.status.tsv         # stages, elapsed time, failures and log locations
├── module07.summary.tsv        # completed gene/mode metrics
├── module07.checkpoint.rds     # resume history/settings
├── module07.report.txt         # completion and limits
└── GENE_SYMBOL/
    ├── GENE_SYMBOL_collapsed_attempt1.*
    ├── GENE_SYMBOL_collapsed_validation_attempt1.*
    ├── GENE_SYMBOL_uncollapsed_attempt1.*
    └── GENE_SYMBOL_uncollapsed_validation_attempt1.*
```

Module 8 writes `results/module08/module08.report.md` plus combined gene/fit/branch/contrast/source TSVs, an overview PNG and a session record. Start with the report, follow links to evidence, and use [RESULTS_GUIDE](RESULTS_GUIDE.md) for individual columns. The combined contrast table contains ready comparisons; unavailable requests remain in the original per-gene contrast tables.

The tutorial deliberately isolates its data at `inputs/tutorial/` and outputs at `results/tutorial/`, including its own module07/ and module08/ folders. Running scripts without the tutorial's explicit paths uses their ordinary defaults instead.

## Generic operation and reproducibility

The reporting script derives gene names, clone IDs and findings from compatible saved workflow results; it is not tied to the current five real genes. It needs matching prepared Modules 2–3 inputs and the Module 7 checkpoint/results at accessible paths. It does not import arbitrary results from an unrelated analysis. Keep the source folders alongside reports for links and retain prepared input paths for regeneration.

Scripts preserve existing outputs. Use new prefixes/directories for intentional reruns; use `--resume` only for an identical Module7 run. Failed/interrupted stages receive another attempt suffix. Input/script/settings hashes prevent accidental mixing. A checkpoint cannot replace deleted model files. Reports record source hashes; numerical provenance belongs to the run that produced them, even if documentation is subsequently improved.

Validation includes the reviewed real-data five-gene panel, the independent synthetic tutorial and consistency/failure tests. That is not universal validation across assays or biological designs. [REPRODUCIBILITY.md](REPRODUCIBILITY.md) records the tested package reference and limits: exact-version automatic environment restoration is not yet tested.

## Common output contract

Both single-gene fitters 04/06 create eight files, including comparison.png and selected_tree.png, automatically. Shared validator 05 creates seven files, including stability.png, for either explicit tree mode. Panel 07 calls the same fitters/validator and requires the same files for every gene/mode. Report 08 verifies and links these figures.

The three comparison panels are observed expression by clone, observed versus training-fitted expression, and largest available descriptive contrasts. Mode-specific contrast meanings and clone/cellular tree resolution remain different; the output is uniform without claiming identical scientific interpretation. No EN fitted or no EN selections produces an explicit note on the topology view. To restart after an implementation change, use fresh consistent outputs, not an old checkpoint; follow [TUTORIAL's](TUTORIAL.md) clean-run instructions.

Shared 05 validation is named after its input fit:04 uses module04_validation and 06 uses module06_validation. These are output prefixes, not additional script numbers. Supply the explicit pilot/prefix pairs shown in [README](../README.md) and [TUTORIAL](TUTORIAL.md); per-gene panel validation prefixes already include their gene and tree mode and are unchanged.
